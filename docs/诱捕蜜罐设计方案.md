# SSH诱捕蜜罐完整设计方案

## 一、整体架构设计

核心思路是**端口分流 \+ 欺骗环境 \+ 严格隔离**，将攻击者引流到蜜罐中，真实服务隐藏在非标准端口并受防火墙保护。

### 端口规划

|端口|服务|说明|
|---|---|---|
|22|SSH 蜜罐（Cowrie）|对外暴露，吸引扫描和暴力破解|
|1222|真实 SSH 服务|仅管理员知晓，建议配合 IP 白名单|
|2222|Cowrie 内部监听|iptables 将 22 流量重定向至此|

### 流量流向

```Plain Text
外网攻击者 → 端口22 → iptables重定向 → 端口2222(Cowrie蜜罐) → 记录全部攻击行为
管理员 → 端口1222 → 真实sshd → 正常管理服务器
```

## 二、蜜罐选型与欺骗能力分级

针对你的需求，推荐**中交互蜜罐**方案，平衡欺骗真实度与安全性。

### 方案对比

|方案|真实度|安全性|部署难度|推荐场景|
|---|---|---|---|---|
|低交互（仅模拟握手）|低|极高|简单|仅统计扫描数据|
|**中交互（Cowrie）**|**高**|**高**|**中等**|**诱捕 \+ 取证，推荐**|
|高交互（真实系统代理）|极高|较低|复杂|深度威胁研究|

**推荐使用 Cowrie**，它是目前最成熟的开源 SSH 蜜罐，具备完整的文件系统模拟、命令执行仿真、会话录制能力，绝大多数自动化攻击工具和脚本小子无法识别。

## 三、核心欺骗设计：让攻击者信以为真

这是蜜罐成败的关键，需要从多个维度模拟真实服务器特征。

### 1\. SSH Banner 伪装

- 模拟真实的 OpenSSH 版本 banner，如 `SSH-2.0-OpenSSH_8.9p1 Ubuntu-3ubuntu0.1`

- 避免使用蜜罐默认 banner（Cowrie 默认会暴露特征）

- 与你真实服务器的系统类型保持一致（如 Debian/CentOS 风格）

### 2\. 认证阶段欺骗

- **故意设置弱密码可登录**：如 `root/123456`、`admin/admin` 等常见弱口令

- 暴力破解一定次数后 "成功"：前几十次失败，然后某次允许登录，让攻击者觉得 "破解成功了"

- 配置 `userdb.txt`，放入常见用户名密码组合，使爆破工具能跑出 "成果"

### 3\. 文件系统仿真

Cowrie 内置了完整的虚拟文件系统，需要进一步优化：

- 添加伪造的业务文件：`/var/www/html/index.php`、`/root/backup.sql` 等

- 放入看似敏感的假数据：伪造的配置文件、假密码本、假数据库备份

- 模拟真实的进程列表、用户登录记录、系统日志

- 允许攻击者创建、修改、删除文件（仅在虚拟环境中）

### 4\. 命令响应真实化

- 支持 200 \+ 常见 Linux 命令：`ls`、`cd`、`cat`、`wget`、`curl`、`ps`、`who`、`netstat` 等

- 命令输出要有真实系统特征：CPU 信息、内存使用率、网卡信息都要伪造得合理

- 加入随机延迟：模拟真实系统的命令执行耗时，避免秒回暴露蜜罐特征

- 部分命令故意报错或 "不存在"，符合真实服务器的软件安装差异

### 5\. 反指纹识别（对抗高级攻击者）

老练的攻击者会用特定命令检测蜜罐，需要针对性规避：

|检测命令|蜜罐特征|应对方案|
|---|---|---|
|`cat /proc/self/exe`|返回空或异常|模拟返回真实路径|
|`dmesg`|输出为空或固定内容|生成真实内核日志输出|
|`uname -a`|固定字符串|随机化内核版本|
|命令响应速度|全部瞬时返回|加入随机执行延迟|
|`ls /proc/`|进程数异常少|伪造更多进程条目|

> 进阶方案：开启 Cowrie 的 LLM 模式，用大模型动态生成命令响应，极大提升指纹识别难度。

## 四、部署实施步骤

### 第一步：迁移真实 SSH 端口

1. 修改 sshd 配置：

```bash
vim /etc/ssh/sshd_config
# 修改或添加
Port 1222
# 建议同时禁用密码登录，改用密钥
PasswordAuthentication no
PermitRootLogin prohibit-password
```

2. 重启服务并验证：

```bash
systemctl restart sshd
# 先保持当前会话不关闭，新开窗口测试1222端口能否登录
ssh -p 1222 root@你的IP
```

### 第二步：部署 Cowrie 蜜罐（Docker 方式，推荐）

```bash
# 创建工作目录
mkdir -p /opt/cowrie/{etc,var/log,var/lib}

# 编写docker-compose.yml
cat > /opt/cowrie/docker-compose.yml << 'EOF'
version: '3'
services:
  cowrie:
    image: cowrie/cowrie:latest
    container_name: cowrie-honeypot
    restart: always
    network_mode: host
    volumes:
      - ./etc:/cowrie/etc
      - ./var/log:/cowrie/var/log
      - ./var/lib:/cowrie/var/lib
EOF
```

### 第三步：iptables 端口重定向

这是核心配置，将 22 端口流量静默转发到蜜罐：

```bash
# 将22端口流量重定向到Cowrie的2222端口
iptables -t nat -A PREROUTING -p tcp --dport 22 -j REDIRECT --to-ports 2222

# 确保1222端口的真实SSH不受影响（已经直连sshd）
iptables -A INPUT -p tcp --dport 1222 -j ACCEPT

# 保存规则（Debian/Ubuntu）
apt install -y iptables-persistent
netfilter-persistent save
```

> **重要**：务必先确认 1222 端口能正常登录，再执行 22 端口重定向，避免把自己锁在外面。
>
>

### 第四步：蜜罐精细化配置

编辑 `etc/cowrie.cfg`，关键配置项：

```ini
[ssh]
listen_endpoints = tcp:2222:interface=0.0.0.0
# 伪装成真实OpenSSH banner
ssh_version = SSH-2.0-OpenSSH_8.9p1 Ubuntu-3ubuntu0.1

[honeypot]
# 主机名伪装
hostname = web-server-01
# 模拟的操作系统
os_version = 5.4.0-42-generic

[shell]
# 允许攻击者登录后进入shell
enabled = true
```

编辑 `etc/userdb.txt`，设置可登录的弱账号：

```Plain Text
root:x:123456
root:x:password
admin:x:admin
test:x:test123
```

## 五、安全隔离与防护

蜜罐本身是 "诱饵"，必须防止被攻击者利用后反咬真实系统。

### 1\. 网络隔离

- 使用独立用户运行蜜罐进程，禁止 root 权限

- Docker 部署时使用非特权容器，禁用 `--privileged`

- 限制蜜罐的出站流量，防止被用作攻击跳板：

```bash
# 禁止蜜罐IP访问内网（如用独立容器IP）
iptables -I FORWARD -s 172.17.0.0/16 -d 192.168.0.0/16 -j DROP
```

### 2\. 资源限制

- 限制 CPU、内存使用，防止攻击者耗尽服务器资源

- 限制并发连接数，抵御针对蜜罐本身的 DDoS

### 3\. 文件系统隔离

- 蜜罐内所有文件操作都是虚拟的，不会写入真实磁盘

- 攻击者上传的文件会被捕获保存，但不会执行

- 下载的恶意样本自动存入 `var/lib/cowrie/downloads/` 供分析

## 六、监控与告警

蜜罐的另一价值是威胁感知，任何访问 22 端口的行为都可视为可疑。

### 日志位置

- 会话完整记录（可回放）：`var/lib/cowrie/tty/`

- JSON 结构化日志：`var/log/cowrie/cowrie.json`

- 捕获的恶意文件：`var/lib/cowrie/downloads/`

### 关键告警点

1. **暴力破解告警**：短时间内大量密码尝试

2. **登录成功告警**：攻击者进入蜜罐 shell（高优先级）

3. **危险命令告警**：执行 `wget`、`curl` 下载木马，或尝试提权

4. **端口扫描关联**：结合其他端口扫描数据，标记攻击源 IP

### 集成方案

- 可将日志接入 ELK、Graylog 或 SIEM 系统

- 配合 fail2ban，将攻击 IP 加入真实防火墙黑名单

- 配置邮件 / 钉钉 / 企业微信告警，实时通知攻击事件

## 七、进阶增强建议

### 1\. 多端口诱捕

除了 22 端口，还可开放其他常见端口增加诱捕面：

- 23 端口：Telnet 蜜罐（Cowrie 自带支持）

- 3306 端口：MySQL 蜜罐

- 80/443 端口：Web 蜜罐（如 Glastopf）

### 2\. 真实系统代理模式

如果需要极高欺骗度，可配置 Cowrie 为代理模式，后端接一个真实的隔离虚拟机或 LXC 容器。攻击者操作的是真实系统，但所有流量都经过蜜罐记录和审计，且后端系统与生产网络完全隔离。

### 3\. 地理伪装

根据服务器所在地区，配置对应的时区、语言、主机命名风格，让环境更 "地道"。

## 八、部署检查清单

部署完成后，按以下步骤验证：

1. ✅ 1222 端口能正常 SSH 登录（管理员通道正常）

2. ✅ 22 端口连接显示正常 SSH banner，无蜜罐特征

3. ✅ 使用弱密码能成功登录 22 端口蜜罐

4. ✅ 蜜罐内执行命令有真实输出，无法访问真实系统

5. ✅ 所有操作都被完整日志记录

6. ✅ 蜜罐出站流量受限，不能作为跳板攻击内网

7. ✅ 告警机制正常触发

这套方案的核心价值在于：**攻击者的注意力和攻击资源全部消耗在 22 端口的蜜罐上，几乎不会去扫描 1222 这类非标准端口**，从而让真实 SSH 服务隐身于噪声之中。即使有攻击者扫到 1222 端口，配合密钥认证和 IP 白名单，破解难度也极大提升。
